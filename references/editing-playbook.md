# 剪辑施工方法

每次从实际内容出发，不按固定秒数堆效果。先锁保留内容，再决定观众在每一段应看人物、资料还是关系。

| 内容任务 | 可选做法 | 需要检查 |
|---|---|---|
| 完整解释 | 稳定人物画面和跟读字幕 | 条件、限定和尾字保留 |
| 关键判断/转折 | 轻裁切或短重点字 | 不切断手势、不让字幕跟着运镜缩放 |
| 同级清单 | 同规格标签逐项出现、保留前项 | 顺序、单位、对齐和阅读时间 |
| 对照 | 左右同尺度的真实内容或明确标注的示意 | 不把示意伪装为真实界面 |
| 操作证据 | 实际录屏/截图，人物让出主要区域 | 信息可读、素材来源真实 |
| 数字/条件 | 对应词出现时给短重点 | 不提前泄露后句结论，数字一致 |
| 情绪落点 | 保留人物反应，少量声音点题 | 不用音效歪曲原意 |

施工单至少记录：成片起止、实际原话、观看任务、人物与资料主次、图层顺序、阅读停留、字体、声音、资产、执行后端和检查状态。用 `planned / implemented / verified` 区分设想、渲染和实际审阅。

按 [效果格式](effects-schema.md) 实施有限的固定裁切、画框、静态文字和已有声音；手动关键帧和视频/人像层按 [图层格式](layers-schema.md)。不可用的功能写清缺口；不要把图文脚本称为自动综艺剪辑引擎。

先用代表性短段验证。需要比较时使用同一段内容与相同源素材，不用效果数量或点赞数据证明质量。正常速度带声检查入场、阅读、退出和剪口，不以三张静态截图替代。
