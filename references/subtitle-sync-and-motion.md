# 字幕同步、末遍取舍与真实运动质量

完整剪辑时必读。字幕“文字像原话”“时间没有重叠”和文件“标称60fps”都不足以验收。

## 先选择最后一遍，再制作最终人声

同一录制段落中相同/近似内容的复录、改口或修改，以原片时间顺序中最后一遍为准。删除前面被替代的版本，不按“哪遍更顺/更完整”回选，也不把几遍拼成作者未说过的一句。最后一遍修改了数字、否定、对象、条件或语气时，字幕和重点字一起更新；不要沿用旧版脚本。

先比较语义单元，分清整段重说与只改一个词。只删除被替代内容，保留旁边未重复的必要背景。句内刻意重复强调不是整段复录；若不能分清，结合前后语气、停顿和后续修订局部复核。末遍残缺或专名不清时保留疑点并询问必要信息，不擅自回到早版。

发现复录就记录`retakeDecisions`的旧版区间/原话、末版区间/原话、差异与已审阅状态。`video_pipeline.py`会拒绝“末版未保留”或“已标为替代的旧版仍保留”的时间轴；检测候选与判断最后一遍仍需实际审阅，不声称脚本自动理解重说。

先锁保留区间、原速和顺序，再按同一时间轴连续拼接最终原声为PCM WAV。剪口不得切掉起始辅音、否定、低声尾字或正常呼吸。逐个检查前后约1–2秒的连续声画；身体/手势位置跳变明显时，优先调整同一语义边界的剪点或减少无必要切口。不能用交叉淡化制造嘴型重影，不能加速人声掩盖不顺。

## 字幕时间来自最终人声

1. 对精剪后的最终人声重新转录，核对每句实际保留的文字、用户确认的专名、数字和否定；原片转录只供比较，不沿用原片SRT。
2. 使用最终人声上的真实词级时间戳；文本改动较大、连续错词、重说或低声片段，局部重识别或用本机实际可用的强制对齐器重新定位。ASR词时间不等于强制对齐，按实际方法记录。零时长、倒序、落在无语音处或明显偏移的词必须修正；多个识别模型不一致时不能取平均当真值。
3. **禁止按字数/字符比例均分整句时间；禁止用字符串相似度匹配几个词，再为其余文字线性插值；禁止拿一个段落起止覆盖所有分句。** 不能把匹配率高当作声音同步。无可靠定位时保留待对齐状态，不能猜边界后交正式版。
4. 按相邻词ID组成短句。显示文字必须与这些词一致；标点、换行、英文大小写可规范，不能换词、删词或补写。数字写法/中文同音专名的改动仍需确认并重新核对时间，不做语义等价自动替换。
5. 每条cue绑定`word_ids`；全部发声词按序且只覆盖一次。起点在对应首词附近，终点覆盖尾词，不把上一句残留到下一句；长停顿期间不挂上一句。构建工具默认首词前约40ms、尾词后约80ms并贴帧网格；相邻cue只在已定时词之间分界。
6. 审计容差：起点允许较首词提前≤80ms/滞后≤100ms；终点允许较尾词提前≤60ms/拖后≤160ms。这是检查边界，不是为了通过而统一平移的目标；以正常速度下看懂、听到、尾字完整为准。口播特别密集时拆句，不能任意缩小字或提前一大句。

上方关键词/数字/并列图文也从对应词定位出现时间，不能整段平均分配或提前显示后半句结论。字幕SRT和烧录图层使用同一份锁定plan，都是半开区间`[start,end)`。

## 本地证据与导出工具

先用`video_pipeline.py render-base`得到精剪底片及返回的`voiceReference`（同时间轴PCM）。在这条PCM上运行已有本地ASR。下面路径均为绝对路径；命令中的`python`应换成已验证运行时。

```sh
python /absolute/skill/scripts/caption_sync.py import-whisper /work/final-voice-asr.json --audio /work/cache/edited.wav --plan /work/plan.json --out /work/word-evidence.json
```

导入不会自动标为已审阅。复核文本、专名、异常词与时间后更新`review.text_reviewed`和`ambiguous_word_ids`，记录实际做过什么。没有听审时`review.audio_reviewed`保持false；不能为了过检查伪造时间或改成true。独立强制对齐结果可按同结构导入：`alignment_method`写实际方法，`words`含唯一整数`id`、`text`、`start`、`end`，并绑定真实PCM哈希和`timeline_sha256`。工具不安装或实现强制对齐器。

分句文件是一个列表，例如：

```json
[
  {"word_ids":[0,1],"text":"按对应两个词的实际文字填写"},
  {"word_ids":[2,3,4],"text":"按后续三个词的实际文字填写","keyword":"实际出现的关键词"}
]
```

```sh
python /absolute/skill/scripts/caption_sync.py build /work/plan.json --evidence /work/word-evidence.json --groups /work/caption-groups.json --out /work/aligned-plan.json
python /absolute/skill/scripts/caption_sync.py audit /work/aligned-plan.json --out /work/caption-sync-check.json
```

它核对最终PCM哈希、锁定时间轴、逐词覆盖/顺序、文本与词对应、每条cue首尾误差和帧网格。改剪口、速度、fps、顺序或音轨后，旧证据失效，必须重新对齐。旧的`text_reviewed_after_cuts`不能绕过跨剪口字幕重建。它只查证据一致性，无法证明对齐器本身正确，也不检查烧录画面实际显示了什么。

`subtitle_renderer.py`和`video_pipeline.py srt`正式导出会拒绝缺少或失效的证据。只有工作目录中的预览允许`--draft-unverified`，并在文件名/报告中标未对齐草稿，不得宣称正式同步通过。自写渲染器或其他编辑器也必须执行同等检查，不能换后端绕过。

## 帧率与码率

- 先看原片真实帧PTS、可变帧率、运动重复/冻结和旋转；同时记录`r_frame_rate`与`avg_frame_rate`。计划命令按源名义帧率选择恒定时间网格，VFR或名义/平均值异常时需结合实际PTS修正，不能只信头信息。
- 1080P高帧率优先：原生60或59.94保留其节奏，50源保留50，避免50→60机械重复形成不均匀节奏。高于60原速素材通常用60交付，若用户要求保留更高帧率则显式选择。25/30等低帧率先保持原生；用户要求提高真实观感时，可对同源连续镜头单独测试光流插帧到50/60，检查嘴型、手指、眨眼和边缘后再采用。不可跨剪口插帧，不改音轨速度；失败保留源节奏并说明，不把复制帧称为运动改善。
- 帧率在剪辑/图层/mask/字幕产生前锁定，后续所有渲染沿用同一网格；不能最后对旧有损成片加`-r 60`冒充升级。从原片重导，维持每段帧数和PCM样本映射，防止多剪口逐段累计偏移。
- 质量优先默认软件H.264、`slow`、高码率VBR目标40Mbps，最大60Mbps、缓冲120Mbps；这些是编码设置，不保证实际每秒或平均都等于40Mbps。硬件仅显式选用，目标40Mbps，需同源运动样段比较。可另选CRF14恒定质量，但CRF不承诺码率。中间画面保持无损编码模式，不串联多次有损压缩，不把低清代理放大成高清。
- `verify`按视频包字节统计真实平均码率、固定一秒分桶峰值，并核对完整解码帧数、逐帧PTS、尺寸和音画起点。码率不足预期时检查实际编码命令、误用缓存/代理和编码器；不能仅改JSON或填充码率数字。高码率不能恢复源片缺失的细节。
- 运动检测记录主体区域近重复帧候选、连续重复长度，再对比同一原片运动。人物自然静止、编码差异或新叠字会影响指标，不能自动判定卡顿或通过。正常速度看连续运动和每个剪口；帧数正确、全片解码成功、三张静态样帧都不能替代。

## 交付验收分开记录

每条全片逐句检查：说什么/何时说、字幕何时出入、实际烧录文字、重要数字/否定/专名、重说末版和全部接缝。抽取字幕切换前后帧可辅助，不足以替代正常速度带声审阅。每个剪口保留播放审阅结果；发现字幕错位后回到该句词证据和相邻剪口修正，不能用全片统一偏移掩盖局部错误。

分别记录`technical_check`、`caption_evidence_check`、`rendered_caption_reviewed`、`motion_playback_reviewed`、`audio_reviewed`。无法播放或听音时相应项保持未完成，说明范围；文件只能标清待播放/待听审候选，不能再称“字幕和流畅度全部检查通过”。用户未要求重剪旧片时，只更新skill与必要测试，不恢复或生成旧成片。
